# Fix History — 2026-08-19

## [WITHDRAWN-SERIAL-FETCH-BUDGET] Step 113 parallelised fetch — 11:20 AEST
**Symptom:** `detect_withdrawn.py` (step 113) aborted early with "runtime budget exceeded" every night for a week. At ~26s per BrightData Web Unlocker round-trip and 221 live listings, a full pass needs ~95 min against `MAX_RUNTIME_MIN` = 40, so a complete sweep was arithmetically impossible and withdrawn listings sat undetected.
**Root cause:** the main loop fetched one listing at a time. The 26s is pure network wait — no local CPU, no shared state — so the step was ~100% idle by wall clock.
**Fix:** parallelised ONLY the fetch. `worklist` is now processed in chunks of `2 x FETCH_WORKERS`; each chunk's `check_listing_status` calls resolve concurrently via `ThreadPoolExecutor.map` (order-preserving), then the chunk's results are iterated IN ORDER on the main thread where every DB write still happens serially, unchanged. Workers run `_resolve_status()`, which never receives the collection handle and does no DB access, so no write can originate off the main thread. Worker count from `WITHDRAWN_FETCH_WORKERS` (default 4, deliberately conservative; 6-8 is the target). Wall-clock `deadline` is now checked BETWEEN chunks so an abort never strands in-flight paid requests. Per-item `time.sleep(REQUEST_DELAY)` moved to between chunks.
Circuit breaker changed from consecutive-error counting to a ROLLING WINDOW (`>= WITHDRAWN_CIRCUIT_BREAKER` (15) errors in the last `WITHDRAWN_CIRCUIT_WINDOW` (20) results) — with concurrent completion, "consecutive" described nothing real and one healthy result between failures reset the count to zero. `circuit_broken` semantics and the `⚠ COVERAGE BEHIND` line that `main_site_health_check.py` greps are unchanged.
Round-robin interleaving, per-suburb counters, the rotation cursor field (`withdrawn_last_checked_at`) and `check_listing_status` classification logic are all untouched. Added `--limit N` for testing.
**Verification:** `--dry-run --limit 12` completed in **112.8s** (12 checked, 12 active, 0 errors, robina=4/varsity_lakes=4/burleigh_waters=4 — interleaving preserved) vs ~312s serial, ~2.8x.
**Files:** `scripts/detect_withdrawn.py`
**Recurrence:** First

## [AUDIT-UNPROJECTED-OOM] Step 107 dead 13 nights — unprojected find({}) needed ~13 GB — 19:30 AEST
**Symptom:** step 107 (Database Audit & Validation) hit its 600s timeout on all 3 attempts every night from 2026-08-06 to 08-19 — 13 consecutive nights, 1921s of wall clock burned per run. `stdout.log` was 1 byte. Nothing anywhere reported it.
**Root cause:** `audit_collection()` did `properties = list(collection.find({}))` — no projection, every field of every document across 110 collections materialised into a Python list. The audit only ever reads six fields. Measured: ~1,112 KB/doc × 12,104 robina docs ≈ **13.1 GB of Python heap** on a 15 GB VM already using ~6 GB with swap in use, so it swap-thrashed to SIGTERM rather than OOM-killing (no dmesg entry — part of why it was invisible).
It ran fine in 72.6s on 08-05 and failed from 08-06 onward: **document size changed, not count** (+9% docs cannot explain 72s → >600s). `[COMPS-DETAIL-EXPOSED]` on the evening of 08-05 deliberately persisted per-comparable adjustment detail; `valuation_data` is now ~115 KB of a 149 KB average robina doc. A legitimate schema change walked into an unbounded read pattern that was always fragile. Raising the timeout would not have helped — 600s was already ~6x the real work.
**Fix:**
1. Six-field projection + stream the cursor instead of `list()`. **8.6s / 105 MB peak RSS**, verified with `/usr/bin/time -v`.
2. Populated `EXCLUDED_COLLECTIONS`, which was `[]`. Six collections are keyed on something other than suburb (`propradar_sold`, `propradar_coverage_gaps`, `propradar_gap_enriched`, `unit_valuations`, `unit_statutory_comps`, `property_attributes`) and so reported every document as misplaced: **2,731 false positives, zero true ones**. Each verified as genuinely cross-suburb before excluding. Post-fix the audit finds **0 misplaced across 411,165 properties / 104 collections** — so the 416 reported on 08-05 were false positives too, and there was never a real misplacement problem.
3. Rule 7: wrapped the full sweep in `job_run("database_audit", cadence_hours=24)` — it had no heartbeat at all, so it was absent from the Process Registry. A targeted `--collection` run stays unheartbeated (developer action, not the ongoing process).
4. Rule 7b: assert an outcome. `--no-fail` forces exit 0 regardless of findings, so a run that scanned nothing was indistinguishable from a clean audit. Now raises if `collections_scanned == 0 or properties_audited == 0`.
5. Per-collection progress lines, so a future hang is localisable — the entire 110-collection scan printed nothing, which is why the failure could not be placed from logs.
6. Added step 107 to `_STEP_OUTCOME_CHECKS` in `main_site_health_check.py` (two checks: reached its summary at all; misplaced count judged on level, not on non-zero — the [WTA-OPS-020] mistake). Verified both regexes match real step output and return OK.
7. **Latent bug found in the process:** the shared capture-mode consumer does `int(mm.group(1))`, which raises `ValueError` on any comma-formatted number and would have taken the whole health check down. Now strips thousands separators — no-op for the existing bare-`\d+` patterns.
**Why it was invisible for 13 nights:** three independent safety nets and none covered this step — no Rule 7 heartbeat, `--no-fail` inverting Rule 7b, and no row in the step-outcome table.
**Files:** `scripts/database_audit.py`, `scripts/main_site_health_check.py`
**Recurrence:** First for the OOM. The step's failure was logged as `[WATCHDOG] Step 107` on 2026-08-18 without a root cause.

## [EDITORIAL-PRICE-ABSENCE-FALSE] 10 live pages claimed "no price" — 9 of them had one — 20:10 AEST
**Symptom:** while fixing one auction headline, a sweep found published property-page copy framing a missing price as concealment across **24+ properties / 53 fields**. Worse: on **9 of them the claim was factually false** — the page said no price was published while `price` held a real figure. Examples: 150 Christine Ave headline `"Contact Agent" Hides the Price` with `price='$1,599,000'`; 4 Pipit Parade `No price is published` with `price='Offers Over $1,795,000'`; 2a Pipers Point `Price Cut Twice, Then Hidden` with `price='$2,550,000 - Negotiable'`. 120 Christine Ave advertised `offers close 3 August` while `listing_status='under_contract'`, 16 days after the deadline.
**Root cause (two, stacked):**
1. **The prompt never covered it.** `config/property_editorial_prompt.md` PART 8 banned adjudicating the ask (rule 13) and naming competitors (rule 14) but said nothing about a *missing* price, so the model treated statutory silence as a curiosity gap. In QLD the agent is legally barred from giving a price guide on an auction property (POA s216(2)(c)), and a seller instruction gags them on non-auction sales (s216(3)) — the silence is compliance or the seller's own instruction, never concealment. Framing it otherwise is rule 14 in a different costume and puts the seller on the wrong side of the sentence, on a seller-funded business.
2. **`ai_analysis` is written once and never regenerated on a price change** (already recorded as the three-layer editorial staleness defect). Every false page launched as EOI/auction/deadline-sale and later published a figure the editorial never caught up with. The framing bug made a stale field into a false accusation.
**Fix:**
- New PART 8 **rule 17** with the POA s216 reasoning and worked ❌/✅ examples, so the model knows why, not just what. Pushed.
- **10 pages corrected in place** (4 Burleigh Waters, 5 Robina, 1 Varsity Lakes) — the 9 factually false plus the expired-deadline one. Originals preserved in `<field>_previous`; `reframed_reason` records which rule. Replacement copy reuses only facts already present in each document, each traced to its source field.
- Dropped an expired "offers close Monday 17 August" from 5 Camberwell rather than republishing it.
- **Verification:** the contradicted-price sweep now returns **0** across all three suburbs.
**Not yet done — needs Will's approval (framing-only, nothing false):** ~85 fields across ~26 properties still carry absence framing, plus adjacent breaches the sweep surfaced — rule 15 flipper framing (14 Elfin St `Bought for $930K in 2023. Renovated to $1.73M.`, 34 Aruma Ave, 24 Tropicana Cct), rule 14 named portals in headlines (6 properties in Burleigh Waters alone say "Domain's own valuation/estimate"), rule 7b single Fields figures in H1s (9 Gainsborough `$1.5M`, 7 Aruma `$2,330,299`), and ~a dozen `$1.25m`-style number-format breaches. Proposals in `docs/EDITORIAL_ABSENCE_FRAMING_PROPOSALS_2026-08-19.md`.
**⚠ The `verdict` layer was NOT swept.** 9 Auriga, 89 Camberwell, 7 Nardoo, 21 Olympus and 830 Legend Trail all repeat "no price guide has been published" in the body. Same multi-layer trap as Rule 6's `market_pulse` bug — fixing the headline and confirming it live proves nothing about the layer underneath.
**Files:** `config/property_editorial_prompt.md`, `Gold_Coast.{robina,burleigh_waters,varsity_lakes}` (10 docs)
**Recurrence:** Second for editorial framing — `[EDITORIAL-SELLER-ADVERSARIAL]` 2026-08-18 fixed price adjudication and this shape survived that pass, because that sweep looked for verdicts on the ask, not for claims about absence.

## [OFFMARKET-DIRECT-TEST-ROUND-2] Reopen the off-market → mini-site direct test on the V1.5 build + fix sticky `offmarket_arm` — 19:49 AEST
**Symptom:** Will asked what it would take to A/B the current `/off-market` V4 page against the V1.5 house mini-site. Investigation found the mechanism already existed (`off-market-direct-test.mjs`, built 2026-07-21) but had been dormant since the afternoon it shipped: it spent all 10 admission slots between 08:25 and 13:57 that day and self-terminated.
**Root cause (why round 1 can't answer the question):** all 7 round-1 reports built with the **full-AI** pipeline — measured `build_completed_at - build_started_at` of **175–568 s**, so those visitors sat on the building page for 3–9.5 minutes. The `no_llm` default inverted when V1.5 shipped 2026-08-16 (`slot_resolver.py:104` — `no_llm = build_mode != "full"`), and the same path now builds in a **median 4.5 s / p90 22.6 s (n=132)** vs `full` median 354 s (n=42). **Secondary defect:** `useReportAnalytics.ts:106` registered the `offmarket_arm: "v4"` super-property and **never unregistered it**, unlike `OffMarketPage`/`DiscoveryDeck`/`DeckV3` which all do. The label is sticky for the rest of the session, so the `/your-home` view the direct-test redirect produces is filed under `offmarket_arm: "v4"` — silently pooling the exact two arms being compared.
**Fix:**

- `phUnregister("offmarket_arm")` added to the V4 analytics effect cleanup, **after** `sendExit()` so the exit event keeps its own arm tag.
- Corrected stale comment in the loader ("capped at 5" — it was 10).
**Not changed (verified already correct):** `analyse-your-home-submit.mjs:310` already stamps `build_mode = body.build_mode === 'full' ? 'full' : 'no_llm'` and persists it at :475, so new stubs are explicitly deterministic. No edit needed.
**Measurement note:** conversion-rate A/B is not viable here — V4 runs ~103 sessions/week at a 2.21% request rate resting on **3 events** (95% CI 0.0–4.7%); +20% needs 7.2 years, +100% needs 20 weeks. Judge on engagement (`v4_section_read`, scroll ≥50%) and session recordings, which run at 100% sampling (~86–94% capture for engaged sessions).
**⚠ Unverified risk:** the direct-test admission `throw redirect(...)` fires inside a loader whose `headers()` sets `Netlify-CDN-Cache-Control: s-maxage=3600`. If the edge caches that 302, later visitors to the same slug would be redirected **without incrementing the counter** — invisible over-admission. Must be checked live before trusting the counter.

## [ENVELOPE-FALLTHROUGH-MINISITE] Mini-site published valuations the engine had refused — 19:55 AEST
**Symptom:** 30 live `/your-home/` reports published a working range for homes the
comparable-sales engine had explicitly declined as outside its $1M–$2M design envelope.
In 18 cases the published figure was LARGER than the one suppressed, up to
$2,558,100–$4,287,400 (point $3,455,000) on `136-honeyeater-drive-burleigh-waters`.
One affected report, `819-legend-trail-robina`, is a genuine public AYH submission —
a real person was shown a frozen $1,403,399–$1,786,144 for a home the engine declines.

**Root cause:** Two independent holes.
(1) `precompute_valuations.py:4243` expresses refusal by NULLING `confidence.range`.
`SlotResolver._engine_valuation_range()` (slot_resolver.py:1812) reads that null and
cannot distinguish "deliberately declined" from "never valued" — both return None, and
None means fall through to Tier 2 `exterior_evidence`, a tier never backtested at any
price band. `directional_only` / `directional_reason` were never read anywhere in
`scripts/property_reports/`. The identical hazard was solved correctly for units on
2026-08-14 (Tier 0 returns before the house tiers); the envelope never got the guard.
(2) A home the engine NEVER valued has no refusal to read, so even a Tier 0.5 check
cannot fire — `136-harrier-drive-burleigh-waters` reached $2,809,000 off 4 comps
straight through the fallback.
Compounding: `refresh_valuation_slot()` only ever `$set`s, so it could add a range but
never retract one; `refresh_stale_valuations.py --only-missing` (default True) skipped
exactly the docs that already showed a figure — i.e. every doc needing retraction.

**Fix:**
- `slot_resolver.py` — new Tier 0.5 in `working_valuation_range()`: `_engine_declined()`
  reads the engine's own verdict (`directional_only`, else applies the envelope to
  `reconciled_valuation` for subjects computed before the gate landed / outside recompute
  scope) and returns None with `_no_figure_reason` set, feeding the existing `no_figure`
  path that already clears stale ranges.
- `slot_resolver.py` — the envelope now also binds the Tier 2/3 OUTPUT, so a fallback
  point outside $1M–$2M is suppressed even with no engine verdict present.
- `slot_resolver.py` — `refresh_valuation_slot()` can now RETRACT, returning
  `model_range: None` + `no_figure` when the subject is declined.
- `refresh_stale_valuations.py` — loads the subject BEFORE applying `--only-missing`, so
  a declined home is retracted rather than skipped; added the published-point envelope
  check and a `retracted` counter.

**Verification:** 30 retracted across two passes (29 engine-declined + 1 fallback-priced).
Independent re-query, not the script's own count: house-tier reports with a published
point outside $1M–$2M = 0; reports showing a range where the subject is `directional_only`
= 0. Frontend no-figure path already renders ("Working range being prepared") — no
frontend change needed. Poller restarted (caches resolver imports).

**Not fixed / follow-up:** `Gold_Coast.reedy_creek` still holds 4 unsuppressed subjects
with `reconciled_valuation >= $2M` and 1 `directional_only` retaining its range — outside
the target-suburb recompute scope. The mini-site is now protected regardless, but other
surfaces reading those subjects are not. Also: the more generous option (keep the
exterior_evidence range with Will's off-market V4 caveat copy instead of suppressing)
is deliberately deferred — suppression is the smaller, immediately-honest change.

**Files:** `scripts/property_reports/slot_resolver.py`,
`scripts/property_reports/refresh_stale_valuations.py`
**Recurrence:** First for the mini-site path. Related: `[YOURHOME-UNIT-HOUSE-COMPS]`
(2026-08-14) is the same class — a refusal re-answered by a weaker tier.
