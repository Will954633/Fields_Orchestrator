curl -s -o /dev/null -w '%{http_code}' https://api.brightdata.com/request \

curl -s -o /dev/null -w '%{http_code}' https://api.brightdata.com/request \

Measured from a Bright Data US residential IP (zone `gold_coast_agency_level`, `country-us`), `https://fieldsestate.com.au/`:

| UA | HTTP | block page |
|---|---|---|
| bingbot | 200 | no |

| ClaudeBot / Claude-SearchBot | **403** | yes |
| PerplexityBot / Perplexity-User | **403** | yes |

## [YT-7B-COUNTS-UNAVAILABLE-AS-FAILURE] Rule 7b assertion cried wolf on caption-less videos — 10:20 AEST
**Symptom:** The Glover U backfill (525 videos) raised `RuntimeError: attempted N available videos,
transcribed 0` three times at the tail of an otherwise perfect run. The chain survived only because
`glover_chain.sh` does not use `set -e`.
**Root cause:** `youtube_brain_ingest.py`'s Rule 7b assertion fires when a batch attempts videos and
transcribes none — correct when the caption route is broken. But at the tail of a channel the only
videos left were ones whose captions are **disabled at source**. Transcribing zero of those is the
CORRECT outcome. CLAUDE.md rule 7b names two cases — "no work to do" (empty queue, success) and
"could not do the work" (failure). This is a third it does not name: **work that can never be done.**
Premieres were already excluded via `deferred` for exactly this reason; permanently-unavailable
videos were not.
**Fix:** `_is_permanently_unavailable()` classifies `TranscriptsDisabled`, `NoTranscriptFound`,
`VideoUnavailable`, `AgeRestricted`, `VideoUnplayable` as determinate outcomes, counted into a new
`unavailable` metric and subtracted from the assertion's numerator alongside `deferred`.
**This only SHRINKS the numerator — it does not weaken the guard.** Indeterminate errors (proxy 502,
`transcript fetched but empty`, ProxyError) still count as real attempts, so a batch containing even
one of them that transcribes nothing still raises. Verified by unit-testing the classifier against
all five observed error strings.
**Why it matters beyond the noise:** an assertion that fires on correct behaviour gets ignored, and
an ignored assertion is worth less than none — it is the exact route by which the silent failures
rule 7b exists to catch come back. The `given_up` pile check (the second 7b path) is untouched and
still reports the caption-less backlog every run, so these videos stay visible rather than vanishing.
**Result:** Glover U — 484 transcribed, 5 skipped_short (<150 words), 36 genuinely caption-less
(7%). 2,725 units in 273 batches.
**Files:** scripts/samantha/youtube_brain_ingest.py, config/youtube_channels.yaml,
brain1_yt/glover_chain.sh (new)
**Recurrence:** First for this assertion. But it is the SECOND time today that an outcome assertion
has been wrong at the boundary rather than absent — cf. `[PODCAST-BRAIN-INGEST]`, where the episode
guard asserted "did not throw" instead of "output is sane". The lesson generalises: **when writing a
7b assertion, enumerate the determinate NON-success outcomes first.** Empty queue, unreleased,
permanently unavailable and genuinely-broken are four different things, and only the last is a
failure.

## [RL-WEEKLY-MAX-TURNS] Three of seven RL domains produced nothing — a turn ceiling nobody chose — 16:00 AEST
**Symptom:** The 2026-08-16 weekly RL cycle ran seven domains; only four wrote a cycle doc. `seo`, `articles` and `onsite` all exited `rc=1` having produced nothing. onsite was the worst shape: it got far enough to raise REC-onsite-003 and REC-onsite-004 into the ledger, then died before writing the cycle doc — so two recommendations existed with none of the reasoning that justified them.
**Root cause:** `weekly_cycle.sh` capped each `claude -p` invocation at `--max-turns 80`. All three hit it (`Error: Reached max turns (80)` in the run logs). All three failures ran **13–17 minutes**, i.e. nowhere near the 40-minute time budget; the turn count was binding and arbitrary. Compounding it: the heartbeat detail read `claude -p rc=1`, byte-identical to what a failed OAuth refresh writes, so a run that worked hard and ran out of road was indistinguishable on the health board from one that never started. That is why the 08-13 articles failure — the same cause — was never diagnosed.
**Fix:** (1) `--max-turns` 80 → 200, letting `BUDGET_SEC` be the real bound, with a comment recording why the turn count is the wrong ceiling. (2) Added `TURN_FAIL` detection (`grep -qF "Reached max turns"`) alongside the existing `AUTH_FAIL`, passed into the Rule 7b heartbeat block so the detail now reads "hit --max-turns — the agent ran out of road mid-cycle, it did not fail to start". Rule 7b applied to the *detail*, not just the status: an error that cannot distinguish its own cause is only half a heartbeat. (3) Re-launched seo, articles and onsite sequentially rather than losing the week.

## [ARM-GRADE-ONE-CONV] Arm grader called a 2-vs-2 tie a 1.15× winner — 17:35 AEST
**Symptom:** `arm_grader.py` printed `onsite_exp_analyseyourhome_1 / street_range users=114 conv=2 rate=1.8% lift=1.15× → leading` against a control on `users=131 conv=2 rate=1.5%`. **Root cause:** `MIN_TOTAL_CONV` and `MIN_USERS_PER_ARM` gate the EXPERIMENT, not the arm. No significance test was introduced — directional reads on small batches stay (Will, 2026-07-29); what is refused is a verdict no observation supports. Re-graded: the two false verdicts became inconclusive, and the genuine signals survived unchanged (`discover_mode_v1` scroll 16/732 vs swipe 11/658 still leading; the three `for_sale_page_v1` arms still lagging).
