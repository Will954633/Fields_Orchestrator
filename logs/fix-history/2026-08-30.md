## [SEO-QUERY-DIMENSION-BLINDNESS] Every SEO cycle has been reading 9% of Search Console and calling it the channel — 07:00 AEST
**Symptom:** `system_monitor.seo_landing_performance` reported the site taking 5,334 impressions / 78 clicks over 90 days. Search Console's own site total for the identical window is 56,341 impressions / 1,168 clicks. The SEO domain's standing brief records "the channel is SMALL: 3,494 impressions / 52 clicks... Nothing reaches significance" as a governing fact, and every priority set between 2026-07 and 2026-08 was ranked on that number.
**Root cause:** `gsc_pull()` requested `dimensions: ["page","query","device"]` and nothing else. Google does not bucket anonymized (low-volume / potentially identifying) queries — it **drops the rows entirely**. So the query-dimension pull is a ~9.5% sample of impressions and ~6.7% of clicks *by construction*, and every consumer summed those rows to get per-page and site totals. The failure is invisible from inside the data: the numbers are internally consistent, just an order of magnitude small. Two published conclusions were wrong as a direct result — `/off-market/` was written up on 2026-08-23 as "the worst impressions-to-clicks ratio of any large template on the site" at 0.72% CTR when it is in fact the site's engine (34,588 impr, 801 clicks, **2.32% CTR**, the best of any large template), and REC-seo-004 told Will that `/for-sale-v3` sat at position 41.3 "and ranks for none of it" when it is at **position 13.0 with 649 impressions**.
**Fix:** `gsc_pull()` now issues three pulls and tags every row with a `dims` discriminator — `page` (authoritative per-page clicks/impressions/position), `page,query,device` (query attribution only, never to be summed), `__site_totals__` (one row, exact site totals from the `date` dimension, immune to both). The collector logs all three totals and the coverage ratio on every run so the gap can never again be invisible in the log. Bing rows tagged likewise. Added a Rule 7b zero-row assertion (the site has continuous organic traffic, so zero rows is a broken pull, not an empty result) and batched the inserts at 500 — the page dimension alone is 12,480 rows at 90 days and a single `insert_many` that size exhausts Cosmos RU. Updated all four consumers to filter on `dims` so they neither double-count the new rows nor keep reading the sample: `seo_signal.py`, `articles_signal.py`, `article_performance.py`, `seo_pilot_status.py`. `seo_signal.py` also gained a per-template rollup, which is what actually shows the shape of the channel now that 12,480 URLs rank.
**Files:** `scripts/brain2/seo_landing_performance.py`, `16_General_Reinforcement_Learning/seo_signal.py`, `16_General_Reinforcement_Learning/articles_signal.py`, `scripts/article_performance.py`, `scripts/brain2/seo_pilot_status.py`
**Recurrence:** First. Same class as `[FIELD-NAME-GUESS-FALSE-ABSENCE]` (2026-08-09) and CLAUDE.md Rule 8 — a query returned a small number and the number was believed instead of the query being checked. Rule 8 covers absence; this is the same error against *magnitude*, where there is no zero to prompt suspicion.
