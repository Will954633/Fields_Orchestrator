# Fix history — 2026-08-14

## [YOURHOME-FIXTURE-VALUATION] 42% of reports showed the demo home's valuation — 21:40 AEST
**Symptom:** 44 of 106 live `/your-home` reports — including real `under_review` seller
submissions — told the owner their home was worth **$1,900,000 – $2,100,000**. Identical on
every one, because it is 13 Terrace Court, Merrimac's number, not theirs.
**Root cause:** `stubFromDoc()` deep-clones the Merrimac demo fixture (`TERRACE_COURT_13`)
and overlays a working range only inside `if (modelRange && modelRange.low && modelRange.high)`.
With no range the overlay is skipped and the CLONE'S OWN figures survive to render. Same
defect class as `[YOURHOME-FIXTURE-LEAK]` (2026-08-12, the scarcity hero) — that fix
addressed one instance; this is the same trap in the valuation.
**Fix:** Added the `else` branch — clear `mostLikelyLow/High`, `recommendedListingLow/High`,
`reviewedCompCount`, `method`. `formatWorkingRange()` already renders an em dash and
`formatWorkingRangeCompact()` "Under review" for falsy input, so the honest state was
already supported and simply never reached.
**Verified live** on 5 reports: three now read "Working range being prepared", a unit reads
its unit-engine range, a house is unchanged. 0 console errors.
**Files:** `01_Website/src/pages/YourHomePage/YourHomePage.tsx`, `.../data/homeFixture.ts`
**Recurrence:** 2nd of this class ([YOURHOME-FIXTURE-LEAK] was 1st)
**⚠ The class is NOT closed.** `stubFromDoc()` still deep-clones the fixture; every field it
does not overlay is still capable of showing another property's content. Two instances found
by accident, both serious. This needs a systematic pass, not a third patch.

## [YOURHOME-UNIT-HOUSE-COMPS] Units valued against house comparables — 21:15 AEST
**Symptom:** A unit submitted to `/your-home` received a valuation built from HOUSE sales.
**Root cause:** No dwelling-class gate anywhere in the mini-site build. An attached dwelling
fell through the house tiers to `SlotResolver.valuation_model_range()`, whose query filtered
`listing_status` + `bedrooms` + `sale_price` and **not** property type. Measured on sold
stock, 3-bed house median vs 3-bed unit median: **Robina +27%, Burleigh Waters +26%,
Varsity Lakes +21%**. The tell was three unrelated units sharing one range — the suburb's
house median band.
**Fix:** Three layers.
  1. `_is_attached_dwelling()` using the shared `classify_dwelling` (not a local regex — the
     off-market TS route has its own and they disagree at the edges).
  2. Tier 0 in `working_valuation_range()`: attached dwellings read the unit engine
     (`Gold_Coast.unit_valuations`, written daily 04:30) and **never** fall through to the
     house tiers. Honours the engine's own `publishable` flag, so Burleigh Waters units —
     1,302 of which carry a point estimate — correctly render no figure.
  3. Defence in depth: `valuation_model_range()` now filters comparables to the subject's
     own dwelling class, so the defect cannot return via a new caller.
  Also: the resolver now writes `valuation.model_range = None` + `valuation.no_figure` when
  refusing, because the writer only `$set`s — without it a stale wrong range survives.
**Remediation:** `scripts/property_reports/remediate_unit_valuations.py` (dry-run/apply).
16 attached reports found: **14 repaired** onto the unit engine, **2 cleared** (both
`comparables_too_old`). Verified 0 house-tier figures remain on attached dwellings.
**Files:** `scripts/property_reports/slot_resolver.py`,
`scripts/property_reports/remediate_unit_valuations.py`
**Recurrence:** First on /your-home. The same defect is documented off-market as
`[OFFMARKET-UNIT-THIN-RANGE-HOUSE-COMPS]` — so 2nd for the business.

## [YOURHOME-FIXTURE-SWEEP] The demo property was leaking across the whole report — 23:10 AEST
**Symptom:** After fixing two instances of the fixture leak by accident, an audit of
`stubFromDoc()` found the class was far wider than either. On **105 of 105 live reports**:
  - the Process tab's **"For your home"** pane named 13 Terrace Court and quoted a
    cost-of-sale ("$45,000 to $59,500") and a price band ("high-$1.9-millions") for whoever
    was reading it;
  - `valuation.methodNotes` cited **"Merrimac's 46-sale cohort"** as the evidentiary basis
    of the reader's own valuation.
  On 44/105: `activeSouthernGcListings` rendered "only N of **142**" — Merrimac's active
  count. On 32/105: the market stat grid printed Merrimac's figures under the reader's
  suburb name — literally "Active **Robina** listings: **41**".
**Root cause:** `stubFromDoc()` does `JSON.parse(JSON.stringify(TERRACE_COURT_13))` and
overlays only the fields the resolver produced. Every un-overlaid field renders the DEMO
property as the reader's. The guards were written as "overlay if we have data", with no
else — so missing data means borrowed data, silently.
**Fix:** Cleared each leaking field rather than leaving a fallback, and gated the render
sites that had no guard of their own (`FearSection` hides an empty applied pane;
`MarketStateSection` renders each tile only with a real figure; `MarketTab` and
`PositionAtAGlance` drop the denominator instead of borrowing one). Types widened to
nullable so a missing figure cannot silently fall back again.
**Also fixed in passing:** `wageGrowthQoQ` is populated with `rolling_12m_yoy_pct` — median
growth, not wages. It was labelled "Wage growth (YoY)" and sourced "Leading indicator".
Relabelled to "Median growth (YoY)", sourced to the suburb's rolling 12-month median.
**Verified live** on 3 reports: zero occurrences of "13 Terrace Court", "Merrimac",
"of 142" or "46-sale". 0 console errors.
**Files:** `YourHomePage.tsx`, `data/homeFixture.ts`, `components/FearSection.tsx`,
`components/MarketStateSection.tsx`, `components/PositionAtAGlance.tsx`, `tabs/MarketTab.tsx`
**Recurrence:** 3rd of this class in three days.
