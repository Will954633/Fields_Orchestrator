## [OWNER-MAILER-PDF-QR] Owner-Subject Article → printable direct-mail PDF with per-address QR — 05:40 AEST
**Symptom:** N/A (new feature). Will asked for a branch of the Owner-Subject Article workflow that emits a printable PDF carrying a QR code to that address's `/off-market/<slug>` page, for posting to homeowners.
**Root cause:** N/A.
**Fix:** Added `build_owner_mailer.py` — a thin wrapper over `build_owner_article.build()` so every editorial gate (factbook mint check, guardrails, DOM cross-surface consistency) still runs and still hard-fails. On top it: (1) resolves the subject's stored `url_slug` and builds `https://fieldsestate.com.au/off-market/<slug>`; (2) refuses to build if there is no `url_slug` (no QR to a nonexistent page) and, by default, GETs the live off-market page and asserts it resolves 200 as a genuine off-market report before printing a QR to it (`--skip-url-check` for dev only); (3) injects a print-safe, data-framed QR call-out panel (kicker "The full data set for this address", the reader's own data — no sell/appraisal/urgency verb, no CTA) plus a printed URL fallback; (4) renders the article's existing `@media print` HTML to A4 PDF via headless Chrome (Playwright→google-chrome), which is faithful to the inline-SVG charts, data-URI photos and CSS the article already ships. QR is a **PNG data-URI** (not inline SVG — the SVG's intrinsic size fought the flex box and clipped the code) at `error='q'`, `border=4` (mandatory 4-module quiet zone). Verified by decoding the QR back out of the *rendered PDF* with pyzbar for two suburbs (Robina 20 Heidelberg Circuit, Burleigh 3 Fimiston Place) — both decode to the correct per-address URL.

## [OWNER-MAILER-PDF-QR-V2] Mailer: fix blank comparison photos + byline + front QR + per-link print QRs — 06:20 AEST
**Symptom:** Will's review of the first mailer PDF: (1) the "Who is moving" Gold-Coast-vs-Sydney comparison cards printed with **blank image areas**; (2) no author byline; (3) the off-market QR only appeared at the very end, not on the front page; (4) as a printed piece, inline hyperlinks were unreachable.
**Root cause:** (1) `.cmp-img` carries `loading="lazy"`; in a headless-Chrome print snapshot those below-the-fold images never enter the viewport, so they never decode and render blank (the hero, which is not lazy, was fine). The data-URIs themselves were valid (72–143 KB JPEGs).
**Fix (all in the mailer layer — `build_owner_article.py` still untouched):**
1. `html_to_pdf` now runs a JS pass before `page.pdf()` that sets every `img.loading='eager'` and awaits `img.decode()`, so all images (incl. the comparison cards) are painted. Verified: both cards now show the Robina + The Ponds Street View photos.
2. Byline row injected between headline and aerial: Will's hedcut portrait (`…/assets/fields/will-simpson-hedcut.webp`, embedded as a resized PNG data-URI) + "Will Simpson", matching the website ArticlePage byline. Fails soft to name-only if the portrait file is absent.
3. Front-page QR added in the same top row ("Scan for your full data" → the off-market page). Aerial shrunk (`.hero img{max-height:300px}`) to make room.
4. Every **external** hyperlink now carries a small inline QR chip (`add_link_qrs`, 52 px, error='m') so a print reader can reach it; in-document `#ref` citation anchors are left alone. Shared `qr_png_datauri()` helper backs all three QR types.
**Verification:** decoded **all 6 QRs straight out of the rendered PDF** (pyzbar) — front-page + 4 link QRs + end panel, each to the correct URL; repeated for Burleigh Waters (5 distinct incl. `/market-intelligence/Burleigh-Waters`). Visually confirmed cards, byline, front QR and smaller aerial on page 1.
