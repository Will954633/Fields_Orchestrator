## [OWNER-MAILER-PDF-QR] Owner-Subject Article → printable direct-mail PDF with per-address QR — 05:40 AEST
**Symptom:** N/A (new feature). Will asked for a branch of the Owner-Subject Article workflow that emits a printable PDF carrying a QR code to that address's `/off-market/<slug>` page, for posting to homeowners.
**Root cause:** N/A.
**Fix:** Added `build_owner_mailer.py` — a thin wrapper over `build_owner_article.build()` so every editorial gate (factbook mint check, guardrails, DOM cross-surface consistency) still runs and still hard-fails. On top it: (1) resolves the subject's stored `url_slug` and builds `https://fieldsestate.com.au/off-market/<slug>`; (2) refuses to build if there is no `url_slug` (no QR to a nonexistent page) and, by default, GETs the live off-market page and asserts it resolves 200 as a genuine off-market report before printing a QR to it (`--skip-url-check` for dev only); (3) injects a print-safe, data-framed QR call-out panel (kicker "The full data set for this address", the reader's own data — no sell/appraisal/urgency verb, no CTA) plus a printed URL fallback; (4) renders the article's existing `@media print` HTML to A4 PDF via headless Chrome (Playwright→google-chrome), which is faithful to the inline-SVG charts, data-URI photos and CSS the article already ships. QR is a **PNG data-URI** (not inline SVG — the SVG's intrinsic size fought the flex box and clipped the code) at `error='q'`, `border=4` (mandatory 4-module quiet zone). Verified by decoding the QR back out of the *rendered PDF* with pyzbar for two suburbs (Robina 20 Heidelberg Circuit, Burleigh 3 Fimiston Place) — both decode to the correct per-address URL.
**Files:** 14_Articles/Owner_Subject_Article/build_owner_mailer.py (new); README.md (§14 added). Core `build_owner_article.py` untouched.
