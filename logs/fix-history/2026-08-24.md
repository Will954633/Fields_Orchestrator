## [ROTATED-SECRET-NOT-DELIVERED] Rotated .env secrets never reach running daemons — REC-ops-004 — 10:01 AEST
**Symptom:** Rotating a secret in `/home/fields/Fields_Orchestrator/.env` did not reach any already-running systemd service. `fields-voice-agent` and `fields-watchdog` were still holding credentials frozen at their 2026-08-06 start; the stale Bright Data key (`05c1f723…`) returned HTTP 401 while the live `.env` key (`e974dc13…`) returned 200. This is the mechanism that kept Domain.com.au ingestion dead for 3 nights *after* the key was rotated on 2026-08-13 and it was called fixed. 2nd occurrence of the "ran, exited, reported fine, every credential call inside it failed" class ([BUILDER-ENV-EXPORT-GAP], 08-07).
**Root cause:** systemd reads `EnvironmentFile=` once, at unit start. A `.env` edit is invisible to a live daemon until it is restarted. Nothing forced that restart, so rotation depended on a human remembering to bounce every affected service.
**Fix:** Two parts (both approved by Will 2026-08-18 on REC-ops-004).
  1. Immediate: `systemctl restart fields-voice-agent fields-watchdog`; verified voice-agent's held `BRIGHTDATA_API_KEY` now matches the live `.env` key via `/proc/PID/environ`.
  2. Durable (automatic, per Will): `scripts/restart_env_dependent_services.sh` + `fields-env-watch.timer` (every 60s) + `fields-env-watch.service` (oneshot). The script sha256-hashes `.env`, compares to a stored baseline (`logs/.env-watch.hash`), and on change restarts every ACTIVE service whose unit declares this `.env` as `EnvironmentFile` (discovered dynamically, not hardcoded — new services are covered automatically). It only advances the stored hash on a fully clean restart (Rule 7b: never advance a watermark on a failed run), and seeds the baseline without restarting on first observation.
  Chose a hash-diff timer over a systemd `.path` unit: the `.path` inotify watch fired on in-place writes but NOT on cross-dir atomic replace (temp+mv), which is exactly how some rotations write the file — it would have silently missed the case it exists to catch. The timer catches every write pattern deterministically (≤60s latency; rotations are rare).
**Verification:** End-to-end — changed `.env`, timer fired at 10:00:25, detected the hash change, re-delivered to all 17 `.env`-dependent services, all returned active. Unit files copied to `deploy/systemd/` for disaster recovery.
**Files:** scripts/restart_env_dependent_services.sh (new), deploy/systemd/fields-env-watch.{service,timer} (new; live copies in /etc/systemd/system/), /home/fields/Fields_Orchestrator/.env (transient test edits, reverted).
