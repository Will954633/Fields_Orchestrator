## [LISTING-IMAGE-HOSTS-ORB-BLOCKED] 82% of listing photos on hosts a browser refuses — 08:40 AEST
**Symptom:** Competitor cards rendered without photos. Diagnosed initially as "photos missing for
Burleigh Waters"; that was wrong — `images_uploaded_to_blob` is true on 98/99, 51/51, 56/56.
**Root cause:** TWO independent bugs, neither about photo coverage.
  1. **`competitor_matcher.py:884`** — `"imageSrc": _hero_image(c) if is_close else None`. The
     PHOTO was gated on a combinatorial match. Proof it was the gate and not the data: `8 Rice
     Place` appears in two reports built 37 seconds apart, with an image in one and none in the
     other, purely because `is_close` differed per subject. `differenceVsSubject` gating on
     is_close is correct — that is a CLAIM about similarity. A photograph is not.
  2. **Host blocking.** Measured in a real browser (curl returns 200 for all three — these are
     ORB/CORS failures curl cannot see):
         fieldspropertyimages.blob.core.windows.net   1,602 listings   BLOCKED
         bucket-api.domain.com.au                       711 listings   BLOCKED
         blobs.fieldsestate.com.au                      492 listings   loads
     **2,313 of 2,805 active listings (82%) carried a first image that renders broken anywhere it
     is used.** The CDN fronts the same blob store, so the Azure rewrite is a pure host swap —
     verified, identical path returns a 1600px image.
**Fix:** Removed the `is_close` gate. Added `servable_image_url()` rewriting the Azure host to the
CDN, applied on every `_hero_image` return path. `b.domainstatic.com.au` does NOT serve Domain's
`/v1/bucket/image/` path, so those are left as-is and our own store is preferred first.
**Not fixed, deliberately:** no photo backfill. Only **17 of 2,822 (0.6%)** active listings lack
`property_images`, and those carry zero `domain_image_urls` — there was nothing to scrape. Several
are malformed scrape artefacts (an "address" of "Coomera, QLD 4209 house for Sale, $1,202..."). The
nightly is working.
**Files:** scripts/property_reports/competitor_matcher.py
**Recurrence:** 17th of the family. Third instance of "curl said it was fine".

## [SCARCITY-MAP-COORDS] Matching homes were unmappable because the count never kept them — 08:20 AEST
**Symptom:** The V4 scarcity map plotted amenities instead of the homes the section is about. I had
concluded active listings carry no coordinates — 0 of 58 in Burleigh Waters.
**Root cause:** Two things, and the first was mine. (a) I queried lowercase `latitude`, which does
not exist on these documents; the coordinates live in **`LATITUDE`/`LONGITUDE`** (uppercase, from
the cadastral dataset), with `geocoded_coordinates` and `georeference_data` as fallbacks.
(b) `scarcity_features.count_active_matches` uses `count_documents`, so the matching set was never
retained and nothing downstream could place those homes anywhere.
**Fix:** Added `find_active_matches()` + `resolve_listing_coords()` to `scarcity_features.py`,
mirroring the counter's query EXACTLY so the dots can never disagree with the number printed beside
them. Kept separate from the counter because that count is the load-bearing honest number and must
not change shape. Verified: 21 of 21 matching listings resolve coordinates.
**Files:** scripts/property_reports/scarcity_features.py,
15_Off-Market/Page_Redesign_V4/Prototypes/render_prototype_a.py
**Recurrence:** 18th.

## [AERIAL-TITLE-BOUNDARY] Hero aerial now marks the actual parcel — 08:15 AEST
**Symptom:** "A reader looking at a block of roofs cannot tell which one is theirs" (Will).
**Fix:** New `scripts/render_property_aerial.py`. Resolves LOT/PLAN from the document, fetches the
true parcel geometry from Queensland's public cadastral service, caches it on the document as
`cadastral_polygon` (so the API is hit once per property, ever), projects the rings into Static
Maps pixel space and draws the outline with a blurred dark underlay so it survives pale roofs.
Semi-transparent Fields logo top-left over a soft vignette. Correctness check: the fetched parcel
for 28 Wedgebill reports 603.0 m², matching the document's stored land size exactly.
**Colour:** renders `sun` / `gold` / `copper`. Default is **sun** — copper and gold sit in the same
hue family as the terracotta roofs that dominate these suburbs and start to vanish into the
roofline. Legibility beat brand primacy; Will to confirm.
**Files:** scripts/render_property_aerial.py, .../render_prototype_a.py

browser check caught it, via a 404 on an aerial filename that no longer existed.
**Fix:** Restored all four definitions; re-rendered; verified 16/16 pages clean. Never blind-slice
between two function anchors, and never suppress output on a loop whose failure is invisible.
