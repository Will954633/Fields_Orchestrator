## [NETLIFY-BUILD-BROKEN-BRANCH-DIVERGENCE] Website build failing since reel3 commit — 11:15 AEST
**Symptom:** Every Netlify deploy since commit `e943c3f` (23:23 UTC 2026-08-27, "feat(reel3)")
errored at "building site" with exit code 2. The live site was frozen on the last good deploy
(`cfaa5a72`); a newly-pushed feature (Living Map wiring, commit `78a19222`) could not go live
because its deploy inherited the same failure. `error_message` from the Netlify API was only the
generic "Build script returned non-zero exit code: 2" — the build-log endpoint (`/builds/{id}/log`)
returned "Not Found" and `log_access_attributes` was false, so the real error had to be reproduced.
**Root cause:** Branch divergence. `main` and the last-good line (`cfaa5a72`) had `ahead_by=2
behind_by=3` — they forked. `main`'s `src/routes.ts` line 72 registered
`route("price-your-home", "routes/price-your-home.tsx")`, but the three files that route needs —
`src/routes/price-your-home.tsx`, `src/pages/PriceYourHomePage/PriceYourHomePage.{tsx,module.css}`
— existed **only on the diverged `cfaa5a72` line**, never on `main`. So `react-router build`
could not resolve the import → exit 2. It did NOT reproduce locally because the local working
tree (not a git repo — files are managed via `gh api`) happened to contain those files, so a
local `react-router build` resolved them and passed. The divergence had put the route
*registration* on main but left the route *files* on the other branch — a botched merge.
**Fix:** Pushed the 3 missing files (verified md5-identical to the last-good `cfaa5a72` versions)
plus `src/App.tsx` (reconciled to the good version — its only delta vs main was the price-your-home
wiring; verified it carried no reel3 refs, so nothing was dropped) in one commit `cbe13499`.
Confirmed the exact post-fix tree builds clean under BOTH Node 20 (Netlify's version, downloaded
to reproduce) and Node 22 before pushing, to avoid burning another failed Netlify build.
**Files:** src/App.tsx, src/routes/price-your-home.tsx,
src/pages/PriceYourHomePage/PriceYourHomePage.tsx, src/pages/PriceYourHomePage/PriceYourHomePage.module.css
**Recurrence:** First for this exact signature. Related to prior gh-api/local-drift issues
(memory `git_local_drift_gh_api`) — the underlying hazard is that the website "repo" has no local
git, so a local build cannot detect files that exist locally but were never pushed. A `routes.ts`
reference to an unpushed route file is invisible to a local build and only fails in CI.

spread → default payload byte-identical) at the three single-property call sites in
`properties-for-sale.mjs`. `findOne({_id})` there has no projection, so the full doc (incl.
`living_map`) is available. Verified live: `/api/v1/.../:id` → no key by default, `living_map`
with `?livingmap=1`. Headless screenshots confirm the Living Map renders on BOTH /property and
/off-market with zero related console/network errors. Commit `6bfce9fd`.
**Files:** netlify/functions/properties-for-sale.mjs
**Recurrence:** First. Lesson: verify the ACTUAL request path end-to-end, not just the function you

## [LEADFORM-DUP-API-GOTCHAS] Duplicating traffic ads as pre-filled lead ads — 3 API traps — HH:MM AEST
**Symptom:** Building OUTCOME_LEADS lead-form clones of proven traffic ads (launch_subscriber_lead_forms.py) failed three times in a row.
**Root cause:** (1) Lead campaigns default Advantage+ audience ON, which caps age_min at 25 — copying a source ad set's age_min=30 verbatim throws error_subcode 1870188. (2) leadgen_forms names are globally unique per Page and forms CANNOT be hard-deleted (only archived), so a crashed-mid-build orphan form permanently reserves its name → "Form Name exists". (3) A hardcoded fbcdn thumbnail/photo URL 403s server-side (short-lived); passing it as video_data.image_url gives "Invalid image in ad".
**Fix:** (1) pin targeting_automation.advantage_audience=0 when the source didn't set it, preserving the exact age band; (2) unique per-ad form names + persist IDs to json after EVERY create (not just at end) so a crash never orphans; (3) fetch the video's own preferred thumbnail / the photo's largest image via page token at run time and upload to /adimages for a fresh hash.
**Files:** 03_Facebook/Concepts/Subscriber_Lead_Form_Winners/launch_subscriber_lead_forms.py (new)
**Recurrence:** First
