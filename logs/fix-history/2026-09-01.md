## [NEWLISTING-PUBLISHED-INCOMPLETE] New-listing editorial pages published missing valuation, boundary, and floor-plan — HH:MM AEST
**Symptom:** Two published property pages (22/1 Warbler Parade Varsity Lakes `…9d7f`, 7 Beauty Point Drive Robina `…9d7e`) went live with (a) no boundary border on the aerial, (b) no valuation, (c) no login-locked sections, and 22/1 Warbler showing a bathroom photo where the floor plan should be. Not isolated: across published for-sale listings, ~20 have no valuation and ~5 have no `living_map.parcel` boundary.

**Root cause (four independent):**
1. **Bathroom-as-floor-plan** — `floor_plans` is populated at scrape time by a pure keyword rule (`backup_scraper/scraper/hybrid_extraction_poc.py:515 extract_floor_plans`): any image whose Domain alt/url contains "floorplan"/"/fp/" is swept in, no vision/dimension check. Domain mistagged the bathroom photo. Front-end (`PropertyGalleryV2.tsx pickFloorPlan`) shows the first blob URL = `00.jpg` = bathroom. Step 106 only *reads* `floor_plans`; it does not curate it.
2. **No boundary** — both docs have no `LOT`/`PLAN`/`zoning_data.lot_plan` (empty). `render_property_aerial.polygon_for` resolves parcels by **lot/plan attribute only** (not address/point) for for-sale docs, so with no lot/plan → no `cadastral_polygon` → `precompute_living_map` writes `living_map.parcel = null` → no border. Upstream `enrich_zoning_data.py` *requires* LOT/PLAN as input (doesn't derive it) and is **not in the nightly execution order**. Point-in-polygon lookup from geocoded coords does return parcel geometry (recoverable) but the for-sale render path never calls it.
3. **No valuation** — 7 Beauty Point (House): `valuation_data.summary.exclusion_reason = "missing_floor_area"` (48 comps available, blocked only by absent `floor_area_sqm`; it has no floor plan at all). 22/1 Warbler (Townhouse): `exclusion_reason = "misclassified_dwelling"` — outside the detached-house design envelope, so suppression is by design.
4. **No locked sections** — the recent "members soft-gate A/B" (`ForSaleGate`) is wired **only** to `/for-sale-v3`, never `/property/:id`. The property page's separate `PropertyGate` locks Costs/Trade-offs/Legal/Timeline only when `localStorage.fields_lead_signup` is absent; likely already set on the viewing device from prior testing → everything renders unlocked. Timeline lock also needs >1 price-history event (both listings have 1).

**Systemic cause:** editorial auto-publish (`generate_property_ai_analysis.py store_analysis`, step 120) gates **only** on the editorial fact-check outcome (`_verify_outcome`). It has no completeness precondition — a page publishes even when valuation, cadastral boundary, and floor area are all missing. Step 120 `depends_on: [18,117]` (valuation precompute + satellite) are satisfied because those steps *ran*, but they produced no output for these docs and nothing blocks publish (Rule 7b "ran but achieved nothing").

**Fix (this entry):** Corrected `floor_plans` on 22/1 Warbler to the real plan only (`01.jpg`); bathroom URL preserved in `floor_plans_removed_bathroom`, originals in `floor_plans_original`. Remaining items (boundary re-render, floor-area/valuation, publish-completeness gate, ~20-page backlog sweep) scoped and pending Will's go-ahead on priority.

**Files:** `Gold_Coast.varsity_lakes` doc `6a955a826fdb6cafc3519d7f` (`floor_plans`).
**Recurrence:** First.
