## [WPI-STALE-ABS-FILE] Refreshed stale ABS Wage Price Index for "good time to buy" articles — 23:05 AEST
**Symptom:** The quarterly "Is Now a Good Time to Buy?" pipeline (`fields-automation/pipeline/run_is_now_good_time.py`) was emitting the Queensland Wage Price Index as "160.7, December 2025 quarter, +3.3%" and calling it "the most recent reading". **Fix:** Downloaded the current ABS 6345.0 **Table 2b** cube (jun-2026 release, `634502b.xlsx`, QLD series A2600949X, col idx 3 — same layout the reader expects) from abs.gov.au with a Chrome UA (gov 403 on non-browser UA), verified series/column/structure, replaced the local file. Pipeline now reads **162.8, Jun 2026, +3.37%**. Regenerated all three suburb articles + charts with `--all-suburbs --force`. NB: downloaded 634509b (Table 9b, industry×state, different index base) first — wrong table; identified correct one via the file's own Index sheet ("Table 2b").
**Files:** `fields-automation/data/abs_rba/Total hourly rates of pay excluding bonuses all sectors by state original quarterly index numbers.xlsx` (replaced); regenerated `generated/is_now_good_time/{robina,varsity_lakes,burleigh_waters}/`.

**Root cause (four independent):**
1. **Bathroom-as-floor-plan** — `floor_plans` is populated at scrape time by a pure keyword rule (`backup_scraper/scraper/hybrid_extraction_poc.py:515 extract_floor_plans`): any image whose Domain alt/url contains "floorplan"/"/fp/" is swept in, no vision/dimension check. Upstream `enrich_zoning_data.py` *requires* LOT/PLAN as input (doesn't derive it) and is **not in the nightly execution order**. Point-in-polygon lookup from geocoded coords does return parcel geometry (recoverable) but the for-sale render path never calls it.

4. **No locked sections** — the recent "members soft-gate A/B" (`ForSaleGate`) is wired **only** to `/for-sale-v3`, never `/property/:id`. The property page's separate `PropertyGate` locks Costs/Trade-offs/Legal/Timeline only when `localStorage.fields_lead_signup` is absent; likely already set on the viewing device from prior testing → everything renders unlocked. Timeline lock also needs >1 price-history event (both listings have 1).

**Systemic cause:** editorial auto-publish (`generate_property_ai_analysis.py store_analysis`, step 120) gates **only** on the editorial fact-check outcome (`_verify_outcome`). It has no completeness precondition — a page publishes even when valuation, cadastral boundary, and floor area are all missing. Step 120 `depends_on: [18,117]` (valuation precompute + satellite) are satisfied because those steps *ran*, but they produced no output for these docs and nothing blocks publish (Rule 7b "ran but achieved nothing").

**Fix (this entry):**
1. **Floor plan** — corrected `floor_plans` on 22/1 Warbler to the real plan only (`01.jpg`); bathroom URL preserved in `floor_plans_removed_bathroom`, originals in `floor_plans_original`.
2. **Boundary** — root blocker was no LOT/PLAN on the docs, and point-in-polygon from the nominatim geocode fails (both coords land on a **Road Type Parcel**, ~150-185 m off the lot). Built `scripts/backfill_parcel_boundary.py`: resolves LOT/PLAN by **address** against the QLD **Addresses layer** (MapServer/0 — returns authoritative lotplan + rooftop coord per address string), writes LOT/PLAN/`zoning_data.lot_plan`, then runs the standard `render_property_aerial.polygon_for` → `precompute_living_map` → aerial render + `aerial_boundary_url` + WebP derivatives chain. Both aerials visually verified — boundary drawn on the correct single lot. `living_map.parcel` now populated on both. Job self-registers (`job_run`, cadence 24h) with a Rule 7b zero-output assertion.
