   marked `primary_for_goal=True`, so bidding optimised toward page loads. `page_view` still fires on
   every property page load (`PropertyPage.tsx:514`).

  `primary_for_goal=False`.** Chosen over deleting the tags so we keep the measurement but remove the

## [STEP113-ROLLING-SWEEP-FALSE-ALARM] Withdrawn detection alarmed nightly for correct behaviour — 13:35 AEST

## [HEADLESS-INVISIBLE-TO-POSTHOG] posthog-js sends NOTHING from an automated browser — 00:50 AEST
**Symptom:** Repeated end-to-end tests showed zero events reaching PostHog, and I
twice began diagnosing the instrumentation as broken when it was correct.
**Root cause:** posthog-js drops all events from clients it judges to be bots, and

returns normally, no request is made, no error is logged.

`evaluateOnNewDocument`, plus a real UA. Then events flow.

headless check can NEVER confirm PostHog instrumentation by default. It will look
identical to broken instrumentation. Verify against ingested events, not client calls.
