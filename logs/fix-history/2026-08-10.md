# Fix History — 2026-08-10

## [ADS-NO-LEAD-CONVERSION] AYH address submit never reached Google Ads — 09:40 AEST

**Symptom:** Google Ads reported 33 "conversions" across the March/April 2026 campaigns while producing
zero real leads. `Contact Form Click` — the only lead-shaped conversion action — had fired **0 times
lifetime**. Smart Bidding had no seller-lead signal to optimise toward, so any new campaign would repeat
the March result.

**Root cause:** Two independent faults.

1. **The one converting action on the site was invisible to Google Ads.** `AnalyseYourHomePage.tsx` and
   `AnalyseYourHomeV2Page.tsx` never imported `trackGoogleConversion`. Both called a local
   `fireGtag('analyse_home_lead_submit')` helper, which emits `gtag('event', name, {...})` with **no
   `send_to`** — a GA4 custom event that lands in property `G-5C5VS27X42` and never reaches
   `AW-17993173310`. The AYH address submit is the only interaction on the site that yields a real
   seller lead (PostHog, Jul 2026: 316 `/analyse-your-home` pageviews → 15 leads, 4.7%), and Google
   could not see a single one.
2. **The conversion actions that *were* firing were all page views, and all Primary.** `Page view`
   (31 lifetime), `Property Search Click` and `Article Read (30s+)` are `PAGE_VIEW` category yet were
   marked `primary_for_goal=True`, so bidding optimised toward page loads. `page_view` still fires on
   every property page load (`PropertyPage.tsx:514`).

**⚠ This second fault is a recurrence.** `[LAUNCH-BOT-TRAFFIC]` (2026-03-17) found *"a page-view
conversion tag fired on every landing page load (`send_to: AW-17993173310/Rg0OCIGsqIQcEL6S6IND`, value
$1.00), causing Google to report 32 'conversions' that were just bot pageviews. This taught Google's
algorithm to optimise for bot traffic rather than real users."* That fix removed the tag from
`public/launch/{a,b,c}/index.html` **but left the same label wired into the React app and left the
conversion action Primary** — so the identical failure mode stayed live for five months. It is the
documented "feedback loop of doom": all 111 tracked sessions in that campaign came from 11 AWS IPs.

**Fix:**
- Added `ayh_address_submit` to `CONVERSION_LABELS`/`CONVERSION_VALUES` in `gtagConversions.ts` and fire
  `trackGoogleConversion('ayh_address_submit')` at submit-success on **both** AYH pages, alongside the
  existing `phCapture` / `trackMetaEvent` calls.
- Google Ads account `997-572-4211`: created conversion action **AYH Address Submit**
  (`SUBMIT_LEAD_FORM`, `ONE_PER_CLICK`, 90-day click window — the max, because the seller cycle is long),
  `primary_for_goal=True`, resource `customers/9975724211/conversionActions/7715062001`,
  label `AW-17993173310/OW0zCPGB6t4cEL6S6IND`.
- **Demoted `Page view`, `Property Search Click` and `Article Read (30s+)` to
  `primary_for_goal=False`.** Chosen over deleting the tags so we keep the measurement but remove the
  bidding influence. Only the two `SUBMIT_LEAD_FORM` actions are Primary now.

**Verification:** `npx tsc -p tsconfig.app.json --noEmit` clean for the three touched files (repo carries
~210 pre-existing errors, so filtered); `npx vite build` succeeded in 41.6s; label present in
`build/client/assets/gtagConversions-*.js` and both `analyse-your-home*` chunks import it. All campaigns
are PAUSED, so the account change has no live spend impact.

**Files:** `src/utils/gtagConversions.ts`, `src/pages/AnalyseYourHomePage/AnalyseYourHomePage.tsx`,
`src/pages/AnalyseYourHomeV2Page/AnalyseYourHomeV2Page.tsx` (commit `f31b0a18`); Google Ads account
config (no file).

**Recurrence:** Second — page-view-as-primary-conversion previously fixed only on the static launch pages
by `[LAUNCH-BOT-TRAFFIC]` 2026-03-17; the React app and the account-level `primary_for_goal` flag were
missed. Fixed at the account level this time, which covers every surface rather than one page set.
