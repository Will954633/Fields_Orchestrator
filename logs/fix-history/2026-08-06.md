# Fix History — 2026-08-06

## [V4-RESEARCH-BLOCKED-SOURCES] PropertyChat unblocked, Reddit still blocked — 08:15 AEST

**Symptom:** The Off-Market Page Redesign V4 research session (2026-08-05) recorded two sources it could not reach (`EVIDENCE_consumer_voice.md` §1.2): Reddit (entirely) and PropertyChat (HTTP 403). Reddit was flagged as the single largest gap in the evidence base.

**Root cause:**
- **PropertyChat** — avoidable. `propertychat.com.au` 403s a direct fetch from this VM and refuses WebFetch, but the Bright Data Web Unlocker already provisioned in `.env` returns 200. The research agents had no reason to know that `shared/domain_fetch.py`'s Akamai workaround generalises beyond Domain.
- **Reddit** — genuinely blocked on every route: `reddit.com` 403s the VM IP, WebFetch refuses the host, Bright Data refuses it without completed KYC ("not available for immediate residential (no KYC) access mode in accordance with robots.txt"), and all four redlib/libreddit mirrors tested sit behind Anubis bot-checks. The PullPush archive API worked initially, then blocked with *"This website does not provide free scraping resources for agents."*

**Fix:** New `harvest_reddit_propertychat.py`. Harvested 35 PropertyChat threads / 335 posts into `sources/propertychat_raw.json` and wrote `EVIDENCE_consumer_voice_ADDENDUM_propertychat.md`. PullPush's refusal was respected, not worked around — no Reddit data retained. Parent doc updated at §1.2, §4.6 and §5.1 so it does not contradict the addendum.

Three bugs found and fixed during the work, all of which would have produced confident but wrong output:
1. **Silent data loss under rate limiting.** The first Reddit run treated HTTP 429 as an empty result: 127 requests were dropped and it would have written a plausible-looking file missing most of the corpus while reporting success. Now retries with exponential backoff and records `incomplete_queries` in the output.
2. **Every PropertyChat post stamped with the harvest date.** A whole-page date scan matched the forum's "recent activity" sidebar rather than the posts, dating a 2007 thread as 2026-08-05. Dates are now read from within each `<li id="post-N">` block. This would have destroyed the document's staleness convention.
3. **Quoted text attributed to the wrong member.** XenForo renders inline quotes as `<div>`, not nested `<blockquote>`, so tag-stripping left one member's words inside another's post — a misattribution in a quotation-based evidence document.

**Substantive research outcome:** the addendum revises §4.6 (the "is this priced fairly?" need is *articulated*, not merely inferred) and reframes §3.1 (the portal appears to *hold* a numeric price for "Contact Agent" listings and withhold it — five independent posters plus a named broker). Two claims are flagged as requiring direct reproduction against live listings before any public use.
