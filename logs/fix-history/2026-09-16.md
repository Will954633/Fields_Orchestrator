## [GC-VS-CAPITALS-DOM] Gold Coast vs Sydney/Melbourne/Brisbane days-on-market comparison — 16:40 AEST
**Symptom:** Will asked to compare GC days-on-market trend against Sydney/Melbourne/Brisbane, scraping matched suburbs "as close as possible with enough power."
**Root cause:** N/A (new feature). No capital-city data existed in any DB. PropRadar gives per-suburb DOM for any AU suburb but SNAPSHOT ONLY (history is a paid tier) and a different DOM basis — so it can't supply a trend and can't be mixed with our Domain-timeline DOM. Decision: measure all 4 cities identically via Domain searchListings DOM.
**Fix:** New scripts/capitals_dom/ module: (1) candidates.py — wide candidate suburb lists; (2) screen_panel.py — PropRadar /suburbs screening to price-matched panels (house median $1.2-1.7M, unit $0.78-1.15M, sales-volume floors) → panel.json; (3) scrape_capitals.py — reuses domain_sold_sync.crawl_suburb (Domain internal GraphQL, Bright Data) to pull sold DOM into system_monitor.domain_sold_capitals; (4) build_capitals_dom_json.py — pools per-city per-type monthly DOM (GC from domain_sold over the 63-composite panel; capitals from domain_sold_capitals over the matched panels), all via the SAME searchListings arithmetic DOM for consistency → public/data/gc_vs_capitals_dom.json. Generalized domain_sold_sync.py:119 state hardcode → sub.get("state","QLD"). Frontend GcCapitalsDomChart.tsx: 4-line comparison, Houses/Units + Window + Range pills, direct end labels. Panels: SYD 17h/29u, MEL 25h/8u, BNE 16h/19u suburbs. Backfill: 68,374 sold rows (61,873 w/DOM), 2016-2026, 0 fail, ~$0.70 Bright Data. Result (trailing-12m house DOM): GC 29d, SYD 26d, MEL 26d, BNE 21d — Brisbane fastest, GC slowest at matched price points. Two heartbeats (domain_sold_capitals, build_capitals_dom_json, 744h). Month-end scrape cron + build wired into run_monthly_market_precompute.sh step 4c.
**Note (same-page consistency):** GC line here uses searchListings arithmetic DOM (soldDate−dateListed) vs the houses/units chart's property_timeline published DOM — verified within ~1-3 days (GC houses 29d both ways), so no visible conflict; each chart's basis is noted.
**Bug caught in verification [GC-CAPITALS-SVG-KEYS]:** first live render doubled the lines on window-toggle (DOM probe: 4 paths→7 on 12mo→3mo switch, GC/SYD/MEL labels duplicated). Cause: the series `<path>`, end-label `<g>`, and hover `<circle>` all used the bare city key (`s.key`) and are ALL direct children of the same `<svg>` — duplicate React keys among siblings, which mount fine but orphan old nodes on update. Fix: unique key prefixes (`line-`/`end-`/`hov-`). Same latent collision hardened in GcDomChart (gridline `key={f}`=0 vs marker `key={i}`=0). Lesson: in a hand-rolled multi-series SVG, keys must be unique across ALL sibling element types, not just within one map. Verified via headless DOM probe (path count), not just screenshot.
