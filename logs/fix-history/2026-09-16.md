**Fix:** New scripts/capitals_dom/ module: (1) candidates.py — wide candidate suburb lists; (2) screen_panel.py — PropRadar /suburbs screening to price-matched panels (house median $1.2-1.7M, unit $0.78-1.15M, sales-volume floors) → panel.json; (3) scrape_capitals.py — reuses domain_sold_sync.crawl_suburb (Domain internal GraphQL, Bright Data) to pull sold DOM into system_monitor.domain_sold_capitals; (4) build_capitals_dom_json.py — pools per-city per-type monthly DOM (GC from domain_sold over the 63-composite panel; capitals from domain_sold_capitals over the matched panels), all via the SAME searchListings arithmetic DOM for consistency → public/data/gc_vs_capitals_dom.json. Month-end scrape cron + build wired into run_monthly_market_precompute.sh step 4c.
**Note (same-page consistency):** GC line here uses searchListings arithmetic DOM (soldDate−dateListed) vs the houses/units chart's property_timeline published DOM — verified within ~1-3 days (GC houses 29d both ways), so no visible conflict; each chart's basis is noted.
**Bug caught in verification [GC-CAPITALS-SVG-KEYS]:** first live render doubled the lines on window-toggle (DOM probe: 4 paths→7 on 12mo→3mo switch, GC/SYD/MEL labels duplicated). Cause: the series `<path>`, end-label `<g>`, and hover `<circle>` all used the bare city key (`s.key`) and are ALL direct children of the same `<svg>` — duplicate React keys among siblings, which mount fine but orphan old nodes on update. Fix: unique key prefixes (`line-`/`end-`/`hov-`). Same latent collision hardened in GcDomChart (gridline `key={f}`=0 vs marker `key={i}`=0). Lesson: in a hand-rolled multi-series SVG, keys must be unique across ALL sibling element types, not just within one map. Verified via headless DOM probe (path count), not just screenshot.
