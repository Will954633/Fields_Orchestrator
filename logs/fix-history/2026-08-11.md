# Fix History — 2026-08-11

## [FIELDS-AUTOMATION-4-WORKFLOW-FAILURES] Four Sunday workflow failure emails — two real causes, and only one of them was a real failure — 14:39 AEST

**Symptom:** Will received four "All jobs have failed" emails from `Will954633/fields-automation` for the 2026-08-09 (Sunday) scheduled runs: Market Insight, Market Shift, Market Drivers, State of the Market. The same four workflows had all succeeded on 2026-08-02.

**Root cause — these were TWO unrelated problems, and the two halves are not equally serious:**

1. **Market Insight + Market Shift (a real, 3-week-old outage).** Both run the same script, `pipeline/run_market_insight.py`. Line 968 built a raw metered client — `anthropic.Anthropic(api_key=ANTHROPIC_API_KEY)` — and the script never read `USE_CLAUDE_MAX` anywhere, despite both workflow files setting `USE_CLAUDE_MAX: "1"` and carrying a comment claiming `ANTHROPIC_API_KEY` was merely "an automatic fallback". It was in fact the *only* path. The metered Anthropic org has had no credit since 2026-07-20, so every run 400'd with `Your credit balance is too low` at the Selector agent. There was also a hard `if not ANTHROPIC_API_KEY: sys.exit(1)` precondition that would have blocked the keyless Max path even after the client was swapped.

2. **Market Drivers + State of the Market (not actually failures).** Both correctly did nothing: Market Drivers hit its own recency guard (`⏭️ Skipping — last generated 49 days ago (guard: 60 days)`), State of the Market likewise produced no new article, and `push_to_ghost.py` reported `No articles found matching criteria` for both. They then failed on an *unconditional* `git push`. `actions/checkout` pins the checkout to the SHA the run was **queued** at, not to current `main`. These four runs were queued 21:28–22:36 UTC but the single self-hosted runner only got to them at 23:36–23:39, and other workflows (Watch This Sale, Market Monitor) pushed commits in that window. So local `main` was strictly *behind* remote `main`, and `git push` was rejected as `non-fast-forward` **even with zero local commits** — pushing a branch that is an ancestor of the remote would rewind it, so git refuses. The reflog confirms it: at 09:36–09:38 AEST there are four checkouts resetting `main` backwards to `33e99389` and no `commit:` entries at all. **No content was lost by these two.**

**Fix:**
- `pipeline/run_market_insight.py` now calls `make_client(api_key=ANTHROPIC_API_KEY)` from the repo's existing `pipeline/claude_max_client.py` (the same helper `article_generator.py` has used all along), and the API-key precondition is now `if not ANTHROPIC_API_KEY and not _use_max()`. Verified `MaxClient.messages.create` is signature-compatible with both call sites (string content, no `tools`, `.content[0].text`).
- Added the `git pull --rebase --autostash origin main` guard — already proven in `market_insight.yml` since 2026-07-23 — to the **11 workflows that still lacked it**. All 13 now have it.

**Verification (not assumed — actually run):**
- Ran `run_market_insight.py --dry-run --force` with `USE_CLAUDE_MAX=1` on the VM as user `projects`. `--dry-run` executes the Selector agent, i.e. the exact call that was 400ing. It returned a full insight set and exited 0.
- Confirmed the GitHub Actions runner service runs as `projects` — the same user the test ran as — so the verified Max credential path is the runner's path.
- Dispatched a real `market_drivers.yml` run (31459081317) after pushing. **Green.** Its log shows the new guard on precisely the previously-fatal nothing-to-commit path: `Already up to date.` → `Everything up-to-date`.
- All 13 workflow files re-parsed with `yaml.safe_load`; `run_market_insight.py` byte-compiled.

**Files:** in `Will954633/fields-automation` (NOT `Fields_Orchestrator`) — `pipeline/run_market_insight.py`, and `.github/workflows/{annual_refresh,december_listing_paradox,how_it_sold,is_now_good_time,is_now_good_time_sell,market_drivers,market_monitor,state_of_market,update_pass_monthly,watch_this_sale,what_x_buys}.yml`. **Recurrence: 2nd for both halves — and both recurred because the 2026-07-23 fix was scoped too narrowly.** See `[FIELDS-AUTOMATION-GH-ACTIONS]` in `logs/fix-history/2026-07-23.md`:
- The push race was diagnosed correctly that day but the guard was applied to only **3 of 13** workflow files. The entry even reasoned about pre-emptively covering workflows that had not yet failed — it just stopped at the three that were in front of it. The two that failed on 08-09 were among the ten left untouched.
- The credit-balance half was written off as *"still blocked on Will topping up credits, nothing to fix in code"*. That was wrong, and it cost ~3 weeks of dead Market Insight / Market Shift output. There was code to fix: the workflows were already passing `USE_CLAUDE_MAX=1` and the repo already contained `claude_max_client.py`. The same day, `[APPRAISAL-EDITORIAL-PLACEHOLDER-IN-REAL-PDFS]` migrated a different generator off the same dead API for the same reason — the pattern was in hand and simply was not applied here.

**Lesson:** "blocked on billing" is a conclusion to test, not to record — check whether a credit-free path (Max) is already wired into the caller before declaring an outage external. And when a shared-runner defect is found in one workflow file, fix the class across every file that shares the pattern, not just the ones currently red.
