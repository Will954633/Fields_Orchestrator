## Analysis

### 1. The biggest non-brand page on the site is on page one and earns nothing

`/market-intelligence/{suburb}/overview`, Robina:

| query | impr | avg pos | clicks |
|---|---|---|---|
| «robina property market» | 177 | **8.5 desktop** / 11.3 mobile | 0 |
| «robina property growth» | 139 | **9.3** | 0 |
| «robina investment property» | 86 | 21.6 | 0 |

**402 impressions, zero clicks**, two of the three on page one.

The 2026-08-13 cycle looked at this cluster and concluded "at positions 9.4 and 26.9 the
binding constraint there is rank, not title — a title change cannot fix a page-2 position",
and deliberately did not act. **That was wrong**, and it was wrong because it read
mobile-blended averages and did not split by device. At position 8.5 the constraint is the
click. I am recording that plainly because the same reasoning would have deferred it again.

The title was `{suburb} Property Market Overview (2026): Prices, Trends & Data | Fields Real
Estate` — 82 characters, truncating well before the brand, spending the visible budget on
"Overview", "Trends" and "Data", and containing neither "growth" nor "median price", which
are two of the three things people actually typed.

### 2. Google is running two copies of the market pages, and the legacy copy is winning

The `/market-metrics/* → /market-intelligence/*` migration was 2026-07-31. Three weeks on,
GSC still attributes **479 impressions to the legacy path against 160 to the canonical**, for
the same queries, and the legacy URL ranks **better**: «robina property market» sits at 11.3
on `/market-metrics/Robina/overview` and 14.8 on `/market-intelligence/Robina/overview`.

I checked every way this could be our bug before calling it lag:

- `/market-metrics/*` returns **301** to the canonical (curl as Googlebot) ✓
- `sitemap.xml` holds 28 `market-intelligence` URLs and **zero** `market-metrics` ✓
- `/market-intelligence/*/overview` carries a **self-referencing canonical** ✓
- Every internal link on `/`, `/news`, `/for-sale-v3` and the hub itself points at the
  canonical path ✓ (`App.tsx` still registers a legacy client route, but it is dead code —
  framework-mode `routes/` serves the site)

So: **not a defect, crawl-consolidation lag.** I am stating that explicitly rather than
leaving it out, because "I looked and it was fine" is information. The only lever available
is to make crawlers re-fetch the redirecting URLs, which I did.

### 4. Entity drift, third pass — and why the sensor could not see it

`brand_serp_signal.py` reported "names in use: Fields Real Estate" on 2026-08-22. It sampled
four pages. Outside that sample:

- `/houses-for-sale/:suburb` still emitted the bare `| Fields` suffix — on the goal-1 query
  cluster, precisely where a consistent entity signal is meant to be earned.
- `/about`, `/about/will`, `/about/will-simpson` and `/about/fields-editorial` are **rewritten
  by netlify.toml at status 200 to three hand-written static HTML files**. The React routes
  are inert. My first schema fix of the day went into `about.$authorSlug.tsx` and reached
  nobody; I only found out because the live title did not change after the deploy.
- Inside those static files: `/about` had the non-canonical name and **zero structured data**;
  `about/will-simpson.html` declared `worksFor: {Organization, name: "Fields Research",
  url: "https://fieldsestate.com.au"}`; `about/fields-editorial.html` declared the same as
  `parentOrganization`.

So **three different organization names were claiming the same root URL** — "Fields Real
Estate", "Fields Estate", "Fields Research". That is the fragmentation the conductor directive
names as the reason a competing agent can outrank us on our own brand.

I widened the sensor to nine pages first, then fixed what it found. The widened run caught all
of it immediately, and correctly moved progress from 2/4 to 0/4 — the score got worse because
the measurement got honest.

**Result, measured after the last deploy landed:** `names in use : Fields Real Estate` — one
name, across all nine sampled pages, for the first time. `entity_name_drift` cleared. The two
remaining HIGHs are `thin_same_as` (blocked on profiles existing — REC-seo-003, Samantha) and
`rule5_valuation_in_body` (sent to articles today). Neither is mine to close this week.

### 5. Rule 5 is being breached in live body copy, and it is not mine to fix at source

`/for-sale-v3` carries single-property valuation figures in generated editorial: 4 in
**headline** fields (`hook`, `opinionated_headline` — e.g. "…and a Valuation Model That Says
$2,330,299", "Asking $1,949,000, Comps Average $1,754,364") and 7 in body copy (e.g. "four
closely clustered comparable sales support a reconciled valuation of **$1,726,668**").

Measured against the live `decision-feed-v3` API with a classifier that **excludes** ranges,
asking prices and actual sale prices, all of which Rule 5 permits — the raw count of 68
currency figures is mostly compliant; 11 are not.

`$1,726,668` is the figure the brief records as having already surfaced into the brand SERP.
It was still live ten days later.

This originates in generated `ai_analysis` text, so the durable fix is a generation-time
assertion, not a regex over prose at the render layer. Sent to `articles` as an evidenced
directive with exact field paths, figures and the classifier. Not proposed to Will: it is a
defect against a rule we already hold ourselves to, and the correction is unambiguous.
