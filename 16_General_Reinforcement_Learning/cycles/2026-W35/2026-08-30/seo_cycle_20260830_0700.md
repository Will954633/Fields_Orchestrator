## The headline: I have been reading 9% of Search Console and calling it the channel

This is the finding. Everything else in this document is downstream of it.

`system_monitor.seo_landing_performance` — the table this domain, the articles domain and two
brain2 reports all read — held **only** Search Console rows pulled with
`dimensions: ["page","query","device"]`. Google does not bucket anonymized queries into an
"(other)" row. **It drops the rows entirely.** So that pull is a sample by construction, and
nobody had ever checked how big a one.

Measured 90 days to 2026-08-30, same property, same window:

| pull | impressions | clicks |
|---|---|---|
| `[page, query, device]` — what we stored | 5,334 | 78 |
| `[page]` | 58,466 | 1,178 |
| `[date]` — GSC's own site total | **56,341** | **1,168** |

**9.5% of impressions. 6.7% of clicks.**

The standing brief records, as a governing fact under §6 "Context the agent cannot get from
data": *"The channel is SMALL: 3,494 impressions / 52 clicks over 28 days. Nothing reaches
significance."* Two things are wrong with that sentence. The magnitude is ~10x low, and the
window is wrong too — the collector runs `--days 90`, so the figure was never a 28-day number.
Every priority this domain set between 2026-07 and 2026-08 was ranked on it.

The failure is invisible from inside the data. The numbers are internally consistent, they move
sensibly week to week, and they are simply an order of magnitude small. There is no zero to
prompt suspicion. That is what makes it the same class of error as CLAUDE.md Rule 8
(`[FIELD-NAME-GUESS-FALSE-ABSENCE]`, 2026-08-09) — believing a query's output instead of
checking the query — except against **magnitude**, where Rule 8's tripwire doesn't fire.

## Analysis

### 1. Off-market is the business's organic engine and nobody knew

68% of all organic clicks, at position 6.7, across 10,833 URLs. It is also where the reward
ledger's only off-market conversion came from (`/off-market/3-avocet-avenue-burleigh-waters`,
pos 6.2, CTR 5.9%). I have taken no action on it this cycle — under a stale brief that would be
a new initiative, and after being wrong about this template once already I would rather bring
the corrected picture to the next briefing than act on it the same hour I found it.

### 2. The `/market-metrics` → `/market-intelligence` consolidation finished. Closing the thread.

Last cycle submitted 9 legacy URLs to IndexNow/Bing and asked whether "three weeks becomes four".
Daily GSC impressions on the legacy path: ~50/day through 08-13, then 20, 17, 21, **5, 4, 4, 6,
2**. It collapsed from 08-17. The canonical `/overview` now holds «robina property growth» at
position 9.1 where the legacy URL held 9.5 — the rank transferred rather than being lost. Done.

The 90-day table above still shows `/market-metrics/` with 4,140 impressions; that is history
inside the window, not a live split.

### 3. The market-intelligence blended position looks like it fell off a cliff. It didn't.

Daily avg position on the canonical path ran 5.0–7.0 in early August and 13.9 → 16.0 → 23.1 →
25.9 by 08-27, which reads as a serious ranking loss. It is a **mix shift**: as the legacy path
de-indexed, the canonical URL inherited its long tail, and new low-ranking rows entered the
blend (including junk matches like «varsity lakes startups pulled in $…» at 13 impressions on
the crash-risk page). On the target queries themselves the position held. I am recording this
because the naive read — "our market pages are collapsing" — is wrong and would have sent the
next cycle chasing it.

### 4. Did the 08-23 title rewrite earn clicks? Not measurable yet, and I am not going to pretend.

The overview cluster ran 14 clicks / 1,106 impressions in the 17 days before the deploy and 7
clicks / 330 impressions in the 5 days after — 1.27% → 2.12%. That is **7 clicks**. It is
directionally consistent with the intended effect and it is not evidence. Re-read next cycle
when there is a fortnight of post-deploy data.

### 5. `seo_signal`'s CONVERTING arm had never fired once

`CONVERTING (0)` on every run since the sensor was built. `organic_landing_affinity` is keyed by
**path**; GSC pages are **absolute URLs**; the join looked one up with the other and never
matched a single document. `converters` was therefore 0 on every row, which reads as a
perfectly plausible answer for most pages, so nothing ever looked wrong. The mandate calls this
arm the most valuable one. Fixed — it now returns 13 pages.

### 6. Rule 5 in live SERP copy

`/for-sale-v3`'s single-property valuation figures — the thing I escalated to `articles` on
08-23 — are **fixed**: the copy now leads with a range and states the reconciled point inside
it, which Rule 5 permits. But the same sentence introduced a different and worse problem, below.

## What I did autonomously

**1. Fixed the sensor blindness** (`[SEO-QUERY-DIMENSION-BLINDNESS]`). The collector now issues
three pulls and tags every row with a `dims` discriminator — `page` (authoritative),
`page,query,device` (attribution only, never summed), `__site_totals__` (one row, exact). It
logs all three totals and the coverage ratio on every run, so the gap can never again be
invisible in the log. Added a Rule 7b zero-row assertion — the site has continuous organic
traffic, so zero rows is a broken pull, not an empty result — and batched inserts at 500,
because the page dimension alone is 12,480 rows and one `insert_many` that size exhausts Cosmos
RU. Updated **all four consumers** to filter on `dims`, so they neither double-count the new
rows nor keep reading the sample: `seo_signal.py`, `articles_signal.py`, `article_performance.py`,
`seo_pilot_status.py`. All three of the ones I did not own were smoke-tested to `rc=0` after the
change. `seo_signal.py` also gained a per-template rollup — with 12,480 ranking URLs the
per-page list no longer shows the shape of anything.

**2. Fixed the CONVERTING join** (`[SEO-SIGNAL-AFFINITY-KEY-MISMATCH]`).

**3. Shipped the Rule 5 number-format fix across 60 live SERP fields on 46 properties**
(`[EDITORIAL-ABBREVIATED-CURRENCY-IN-TITLES]`). `articles` handed this to me on 08-23 because
titles and metas are my brief's authority. It mattered more than it looks: REC-seo-001 put these
strings into the live `<title>`, so `$1.4M` was the SERP copy itself. Deterministic,
meaning-preserving expansion only — no rewording. `abbreviated_currency` 32 → 0 in the compliance
checker; verified live on two pages; every before/after saved to
`logs/backups/meta_abbrev_currency_20260830.json`.

**4. Added a `false_confidence_range` check to `editorial_compliance_check.py`**

within a **high-confidence range** of roughly $1,041,000 to $1,325,000"*. That band is exactly
the estimate ±12%, which is a flat percentage the code applies — CLAUDE.md states it contains
the actual sale price **61%** of the time, that it is "NOT a statistical CI, and the code says
so", and that we must "never call it a '90% confidence range'". **65 of 359** properties with
editorial use confidence/interval language; 31 are active `for_sale`; one says literally "90%
confidence". I did **not** mass-rewrite 65 documents of generated prose — the durable fix is a

**5. Submitted the 46 changed property URLs to IndexNow + Bing `SubmitUrlbatch`** (both HTTP 200).

**7. Logged 7 actions to `rl_seo_actions`; four fix-history entries in `logs/fix-history/2026-08-30.md`;
